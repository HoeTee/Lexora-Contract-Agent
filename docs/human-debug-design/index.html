A

范围与核心规则

1 设计范围与确定规则

用户端包含首页、身体部位、感受、问答、确认、扫描、报告、任务和通关页面。后台包含配置、题库、任务库、兜底库、日志、监控和重置功能。管理员账号只通过命令行和 MySQL 管理。

已确定规则：部位和感受确认后锁定。每题点击选项后自动推进。最后一题完成后自动生成情况总结。确认页保留一次最终确认操作。AI 分析从最终确认后开始。AI 超时使用基于身体部位的预置建议。全部时间配置使用滑条。完整输入和模型输出默认记录。

下文默认值、范围和技术选型属于初版实施建议，可以在开发前调整。实际并发容量以模型服务能力和压力测试为准。

B

用户流程 文案与安全

2 用户体验流程

环节 页面与行为
1 开始 点击开始人体 Debug。创建独立会话。显示健康知识与日志保存说明。
2 部位 同一区域显示一张人体图。支持正面、背面、侧面切换。点击部位后显示确认。确认后锁定。
3 感受 点击酸、痛、僵硬、麻、容易疲劳或只是想了解一下。确认后锁定。选项根据部位配置。
4 问答 默认五题。全部使用点击选项。点击即保存并进入下一题。显示第几题和总题数。
5 确认 最后一题完成后自动生成初步情况总结。显示全部答案。允许逐题修改。修改后自动更新总结。点击确认并分析。
6 扫描 立即开始总等待计时并提交 AI。扫描动画循环播放。有效报告返回后进入报告页。到达等待上限则展示兜底报告。
7 报告 显示身体分析、改善建议和现场任务。说明建议来自 AI 或预置内容。点击开始健康任务。
8 任务 显示动作说明及醒目倒计时。默认25秒。计时结束自动进入通关页。
9 通关 显示健康 Buff、通关提示和奖励说明。供工作人员现场确认。
10 结束 点击结束体验或默认停留15秒后自动退出。清除现场会话和页面数据，返回首页。

身体部位覆盖眼睛、头部、颈肩、手腕、胸腹、腰背、膝盖和腿脚。每个视角的点击区域映射到同一 part_id。同一部位不会因为视角不同而改变问答或报告。

确认页修改题目时，点击新选项后直接返回确认页。不得要求用户重答全部题目。若修改答案使后续分支题失效，系统只要求补答受影响题目，再自动更新总结。已确认的部位和感受不能修改。用户需要重新选择时退出并开始新会话。

3 报告与文案规则

初步情况总结由程序模板生成，不调用 AI。它复述已选部位、感受和答案，不添加疾病判断或因果结论。健康 Debug 报告由 AI 生成，并由后端校验。两份报告均使用短句、明确主语和统一术语。每句话说明一个事实或一个动作。保留可能性，不能把相关习惯写成已确认病因。

ASD-STE100 是英文受控语言标准。本项目中文文案采用其写作原则，不宣称通过正式 STE 合规认证。英文文案按指定技能控制句长和表达。中文建议采用一句一个动作、明确对象、减少专业术语的项目规则。

情况总结示例：你选择了颈肩。你感到僵硬。你每天使用电脑超过8小时。你很少活动。你选择的睡眠时间是6至7小时。请检查这些信息。

身体分析应引用具体答案。改善建议应直接说明可执行动作。现场任务只能来自审核后的固定任务库。任务时长和 Buff 由后端配置。AI 仅选择允许的 task_id，不自行编写运动方案。倒计时结束代表游戏计时完成，不能宣称系统验证了动作或改善了健康。

建议数量采用三层控制：Prompt 明确要求 N 条；动态 JSON Schema 将 suggestions 的 minItems 和 maxItems 同时设为 N；后端再次校验长度、重复内容和安全性。N 默认3，允许3至5。校验失败且重试预算不足时使用相同数量的预置建议。不得用重复建议补足数量。

4 安全与特殊流程

安全规则在感受确认、每次答案保存、最终确认和报告校验阶段执行。危险信号规则优先于模型和兜底。规则可关联部位、感受及题目选项。识别到规则命中时进入安全提示页，停止普通报告、健康任务和 Buff 流程。安全提示及规则内容上线前需由合适的健康内容审核人员确认。

选择题应提供能触发安全规则的必要选项。系统只能识别问卷覆盖的风险，不能声称排除了危险。报告禁止疾病诊断、用药、治疗承诺和已改善健康等表述。

AI 超时、网络失败、无效 JSON、字段缺失或不安全输出均可触发预置建议。兜底首先按 part_id 匹配，再可按 feeling_id 和答案标签细化。部位通用模板必须存在。无匹配时采用审核后的最低风险通用模板。危险信号不得被兜底绕过。

用户随时退出。后端标记会话已结束，取消可取消的任务，删除临时状态。模型晚返回的内容只记录调用结果，不写回页面。刷新页面返回首页。长时间不操作先提示，再按配置退出。分析和任务阶段使用各自的期限，避免闲置计时与任务计时冲突。

C

架构 并发与状态机

5 架构与并发控制

建议架构：大屏浏览器 → 反向代理 → 单 Worker FastAPI → 异步模型客户端与 MySQL。前端建议 TypeScript，后端建议 Pydantic 校验，模型调用使用异步 HTTP 客户端，MySQL 使用异步驱动或隔离到线程执行同步调用。技术选型不改变数据契约。

asyncio 默认在一个线程中运行事件循环。多个设备的请求在等待网络或数据库时交替推进。它不是多线程，也不保证上游模型同时推理。async def 内不得直接使用 requests.post、time.sleep 或阻塞数据库调用。CPU 密集任务需要移出事件循环。

模型并发默认5。使用有界等待队列和进程内并发控制器。队列满时立即提供部位兜底，不无限堆积请求。等待队列中的请求同样消耗用户总等待预算。开始扫描时启动总截止时间；排队、请求、重试、校验均受该截止时间约束。

初版仅一个 Worker。增加 Worker 或服务器后，需要共享会话存储和全局并发限制。单进程 Semaphore 不能控制多个进程的总并发。并发配置热更新采用可调整容量的控制器，不替换正在使用的 Semaphore，也不访问其私有属性。降低容量时允许已有请求结束，再停止发放超额许可。

async def analyze(payload, limiter, client, timeout_s):
async with asyncio.timeout(timeout_s): # 覆盖排队和模型调用的总等待时间
async with limiter: # 获取并发许可，退出时释放
return await client.generate(payload) # 使用真正的异步客户端

示例需导入 asyncio。payload 是确认后的输入，limiter 是并发控制器，client 是异步模型客户端，timeout_s 是总预算。调用方必须捕获 TimeoutError 并返回兜底，并在保存结果前校验会话状态。取消客户端请求不一定能停止上游已开始的推理。

6 会话与状态机

状态 进入条件与允许操作
PART_SELECTION 创建会话后选择并确认部位
FEELING_SELECTION 部位锁定后确认感受
QUESTIONNAIRE 感受锁定后逐题作答
SUMMARY_REVIEW 全部题目完成，可修改答案并最终确认
ANALYZING 最终确认后等待 AI 或兜底
REPORT_READY 只接收一次有效报告，可开始任务
TASK_RUNNING 显示倒计时，结束进入通关
COMPLETED 显示 Buff，结束或停留超时后清理
SAFETY_STOP 规则拦截，显示审核后的安全提示
CLOSED 退出、清理或闲置结束，不接受新结果

每次体验使用随机 session_id 和私有会话凭证。session_id 不能单独作为授权依据。每次模型调用使用 request_id，每次答案变更递增 answer_revision。确认时生成 input_revision，并保存 config_version。结果写入必须同时匹配会话、输入版本、请求和当前状态。

最终确认接口支持 Idempotency-Key。相同输入和相同键只创建一个分析任务。报告、倒计时启动和通关迁移使用原子状态转换。任务倒计时以服务端记录的结束时间为依据，前端仅展示剩余时间，避免重复点击重启计时。

D

数据契约与后台配置

7 Schema 数据契约

统一采用 JSON Schema 2020-12。顶层对象禁止未知字段。时间戳采用带时区的 ISO 8601。ID 为字符串。枚举、必填字段、长度和范围由后端校验。输入使用稳定 ID，显示文案由固定版本题库解析。不得仅把不可理解的 option_id 交给模型。

Schema 必填字段及约束
SessionSchema session_id、status、answer_revision、config_version、created_at、expires_at。会话凭证只在创建响应交付，不写普通日志。
BodySelectionSchema part_id、view、feeling_id、part_locked、feeling_locked。view 为 front、back、side。后端验证部位与感受关系。
QuestionSchema question_id、text、options、order、conditions。options 包含 option_id、label、tags。题目与选项 ID 不重复。
AnswerSchema question_id、option_id。单题单选。选项必须属于当前题目。答案数与实际题集一致。
SummarySchema session_id、answer_revision、facts、summary_text。facts 引用 question_id 和 option_id。生成来源固定为 template。
AIInputSchema session_id、request_id、input_revision、config_version、body_selection、answers、report_rules、allowed_task_ids。answers 包含题目和答案显示文字。
AIReportSchema body_analysis、suggestions、task_id。suggestions 恰好 N 条。task_id 必须来自当前允许任务集合。
ReportEnvelopeSchema report_id、session_id、source、fallback_reason、body_analysis、suggestions、task、buff、config_version。source 为 ai 或 preset。
SystemConfigSchema schema_version、config_version、model、runtime、questions、report、safety、ui、logging。密钥读取时只返回是否已设置。
AIInvocationLogSchema request_id、session_id、attempt、input_snapshot、request_body、raw_output、validated_output、status、queue_ms、model_ms、total_ms、error_code、created_at。
SafetyResultSchema blocked、rule_ids、message、allowed_next_action。命中时不得返回普通任务。
TaskSchema task_id、title、instructions、allowed_parts、excluded_tags、duration_seconds、buff_id。由审核任务库生成。

8 后台配置与控件

后台必须登录。时间参数统一使用滑条，显示数值、单位、最小值、最大值和步长。非时间数值参数统一使用两个预设值与自定义三个下拉选项，选自定义后出现输入框。布尔使用开关，枚举使用下拉框，字符串使用输入框，Prompt 使用多行编辑框，密钥使用密码框。

时间配置 默认值 建议范围与步长
ai_total_wait_seconds 总等待 15秒 5至60秒，1秒
queue_timeout_seconds 排队 5秒 0至30秒，1秒
model_timeout_seconds 单次调用 15秒 1至60秒，1秒
scan_cycle_seconds 动画周期 5秒 1至10秒，1秒
task_duration_seconds 任务 25秒 20至30秒，1秒
completion_timeout_seconds 通关 15秒 5至60秒，1秒
session_idle_timeout_seconds 闲置 60秒 30至300秒，5秒
idle_warning_seconds 退出提示 10秒 5至30秒，1秒
retry_backoff_seconds 重试间隔 1秒 0至5秒，1秒
admin_session_timeout_minutes 后台 30分钟 5至120分钟，5分钟

所有时间设置均为滑条，包括日志保留和后台登录有效期。总等待时间具有最高优先级。单次模型超时使用配置值与剩余预算中的较小值。动画周期只决定视觉循环，不强制用户至少等待一次完整循环。模型有效结果返回时可立即显示报告。

模型配置包括协议类型、API 地址、模型名称、API 密钥、温度、Token 上限及结构化输出模式。题库配置包括部位、视角点击区域、感受、题目、选项、条件、顺序和数量。报告配置包括 Prompt、建议数量、文案规则、允许任务和 Buff。安全配置包括拦截规则、提示文案、任务排除规则和兜底模板。运营配置包括首页、奖励说明、全屏提示、动画资源和可选二维码。

日志配置包括完整日志开关、保留时间、导出权限和脱敏规则。默认启用完整输入输出。后台监控显示服务状态、调用次数、成功率、平均耗时、排队时间和失败次数。

配置采用草稿、校验、发布和版本记录。每次发布形成新 config_version。当前会话使用创建时的快照，新会话使用新版本。紧急安全规则可即时对在途会话生效，并记录所用安全版本。模型并发容量按控制器规则即时调整。

数据库地址、端口、凭证、加密主密钥、进程数量和服务监听参数属于启动配置。后台可显示状态和重启提示，不能把它们作为即时业务配置。管理员账号按用户要求在命令行管理。不得把加密主密钥和加密后的 API 密钥放在同一个数据库中。

E

管理日志 接口与存储

9 管理员与日志设计

管理员账户在 MySQL 保存 username、password_hash、role、enabled 和凭证版本。通过命令行工具生成密码哈希后写入数据库，不保存明文密码。修改密码或停用账号后撤销已有登录会话。登录采用安全 Cookie、失败次数限制及适当的 CSRF 防护。后台提供配置变更审计，不提供新增账号入口。

每次体验记录完整选择、答案及版本。每次模型尝试记录完整应用层请求、模型原始输出、有效报告、错误和耗时。即使 JSON 无效或超时，也记录已收到的输出和错误。API 密钥、Authorization、登录密码、会话凭证不属于用户输入，始终排除。

结束体验清除浏览器、后端临时会话和报告缓存。按本方案保留历史日志，供登录后的管理员查询。这与现场清除不是同一操作。首页应明确告知会保存问答和模型输出。日志不主动收集身份信息；健康回答仍需限制查看、导出和保留时间。到期删除完整内容，可保留不含回答的聚合统计。

题库、任务、兜底和安全规则提供相应后台 CRUD 接口。删除被发布版本引用的内容时应保留旧版本，避免在途会话失效。日志导出和重置接口须单独审计。

接口使用统一封装：成功返回 data、request_id 和 server_time；错误返回 code、message 和 request_id。无效输入返回422，身份无效返回401，状态或版本冲突返回409。前端按错误码决定恢复、提示或退出，不显示内部异常堆栈。

MySQL 建议分为 admin_accounts、config_versions、body_parts、feelings、question_sets、task_library、fallback_templates、safety_rules、experience_logs、ai_invocation_logs 和 audit_logs。结构化内容可保存 JSON。request_id 唯一，session_id 和 created_at 建索引。日志表按保留策略清理。临时会话初版放内存，服务重启使其失效，浏览器收到失效响应后回首页。

11 视觉与现场运行

首页、扫描页、任务倒计时和通关页使用大字号、醒目的艺术字体。问题、确认内容、报告和后台使用清晰正文字体。字体需覆盖中文并具有使用许可。颜色对比应保证大屏远距离阅读。正文艺术化不能降低可读性。

按钮参考 Apple 的圆角、轻量阴影、按压缩放、平滑过渡和明确选中状态。触摸按钮及人体区域需要足够大。细小部位可使用扩大命中区或放大视图，并防止重叠选择。动画不阻止点击响应，支持减少动态效果。

现场页面支持全屏、工作人员重置和横竖屏适配。后台入口不出现在普通体验主流程。奖励由工作人员确认，系统不声称已自动发奖。若以后引入二维码或自动核销，需单独增加唯一领奖码、核销状态及防重复领取接口。

12 异常恢复与部署

请求在总等待截止时由后端原子确定最终报告。AI 成功和超时竞争时只能有一个结果生效。页面轮询失败时提示连接问题，重试期间仍使用原截止时间，不延长等待。若后端失联，前端使用启动时获得的审核部位兜底内容或显示服务不可用，并拒绝接收过期结果。

数据库故障时禁止发布配置。AI 日志写入失败应进入有界重试缓冲并显示后台告警。缓冲耗尽时标记日志丢失，不宣称完整保存。密钥错误、配额不足等错误进入监控分类，不把原始敏感异常直接展示给用户。

部署初版采用反向代理、一个 FastAPI Worker、MySQL 和外部模型服务。启用 HTTPS。使用进程管理器或容器自动重启。静态资源本地提供，避免现场依赖外部字体。上线前备份配置和题库，验证数据库恢复、密钥轮换和模型连接。
